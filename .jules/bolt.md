## 2026-07-21 - [Subprocess Spawning Bottlenecks in Bash Loops]
**Learning:** Querying metadata (such as modification times) in a sequential `while read` loop inside Bash using commands like `date -r`, `stat`, or `grep` spawns subprocesses per item ($O(N)$ subprocesses). This results in severe performance degradation even for medium-sized file collections (~100s of files). Leveraging standard batch tools like `xargs stat` alongside $O(N)$ lookup tables in `awk` reduces the subprocess count to a constant number $O(1)$, resulting in massive speedups (over 600x on large directories) while preserving cross-platform compatibility.
**Action:** Always design Unix/Bash utilities to process file lists in bulk (using `xargs` and platform-specific format flags) and compare states in a single high-performance `awk` process rather than looping over items sequentially with subshells.
