## 2026-07-29 - [Optimized Modified Files Check in status Action]
**Learning:** Checking the modification times of a large number of files sequentially in a bash loop (via grep and spawning stat/date in a subshell for each file) is extremely slow and behaves as an O(N * M) performance bottleneck. On a repository with 500 files, this takes over 3.5 seconds.
**Action:** Replace the sequential check with a single batched `xargs stat` call, and use a single O(N) `awk` process with associative arrays to map and compare cached mtimes against the disk mtimes. This reduces the check time from 3.5 seconds down to 0.022 seconds, a 160x speed improvement! Avoid using `strftime` inside `awk` to prevent crashes/syntax errors on macOS BSD `awk`, formatting the output with `stat` directly or string parsing on GNU.
